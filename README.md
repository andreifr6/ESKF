# Simulator Implementation

## Overview
This simulator was designed to implement a low-latency estimator suitable for embedded systems. To achieve high computational performance and embeddability, the implementation was developed in C++, leveraging optimized linear algebra libraries such as Eigen.

The simulator was built in stages. Initially, the delay of the computer vision system was disregarded, allowing the modeling of both the computer vision system and the IMU. Later, delay was introduced and compensated for.

## Simulation Stages
### Stage 1: Initial Simulation
- Real states were simulated and propagated using discrete integration at a frequency at least ten times higher than the filter frequency.
- A CSV file containing linear accelerations and angular velocities commanded at each instant was used.
- IMU measurements were generated by contaminating commanded values with zero-mean white Gaussian noise and bias.

### Stage 2: Delay and Compensation
- Delay was introduced into the computer vision system flow, ensuring measurements provided to the filter were delayed by a known time.
- A delay compensation algorithm was implemented, leveraging precise image timestamps.

## Code Organization
The codebase follows a modular approach, dividing functionalities into classes that represent system components. The Eigen library was used to ensure optimized matrix operations, and efficient data structures like queues and deques replaced standard C++ vectors where applicable.

A UML class diagram illustrates the relationships between different system components. Notably, the Extended State Kalman Filter (ESKF) does not interact directly with the real states (RWSW) but rather through sensor measurements. A shared system time is maintained across all components.

## System Modules

### System Command (SYSCMD)
- Reads a CSV file containing all linear acceleration and angular velocity commands.
- Stores commands in vectors for retrieval during simulation.
- Provides commands based on simulation time through the `getCommand()` method.

### Real World Software/Propagator (RWSW)
- Computes real and discrete values for filter inputs, states, and outputs.
- Simulates IMU measurements and generates inputs for the Camera (CAM) class.
- Uses provided acceleration and angular velocity commands to propagate motion.
- Outputs time-stepped values based on predefined motion equations.

### Inertial Measurement Unit (IMU)
- Simulates IMU functionality, including internal clock and noise generation.
- `updateClock()` method updates the internal IMU clock.
- `checkTimeout()` determines if a new measurement should be acquired.
- `getMeasurement()` generates IMU readings, incorporating noise and biases.
- Stores and retrieves the latest measurement through `getLastMeasurement()`.

### Camera/Computer Vision System Model (CAM)
- Simulates a computer vision system, including position and orientation measurements.
- Implements a sampling system with predefined delay and variance.
- `updateClock()` updates the internal clock.
- `checkTimeoutSampling()` determines if a new measurement should be taken.
- `samplingMeasurement()` generates noisy measurements and simulates camera failures.
